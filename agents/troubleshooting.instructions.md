# Troubleshooting Instructions — Breqy Runtime

## Purpose

This document captures hard-won debugging knowledge from fixing runtime bugs across the engine, agent, and TUI processes. Read this **before** investigating any runtime issue.

---

## 1. System Architecture (Debugging Perspective)

Breqy is three separate processes talking over Unix sockets:

```
TUI (Textual) ──A2A──> Engine Daemon ──A2A──> Agent Subprocess
                         │
                     SQLite DB (sessions, messages, events)
```

- **TUI** connects to engine via `A2AClient` on Unix socket
- **Engine** owns the DB, event bus, session manager, agent registry
- **Agent** connects to engine via `A2AClient`, receives work, calls LLM provider
- Communication is via `Envelope` objects containing typed domain events

### Key Implication

A bug in one process often manifests as silent failure in another. The agent might crash, but the TUI just shows nothing. The engine might reject a message, but the TUI doesn't display an error.

## 2. Common Root Causes (Ordered by Frequency)

### 2.1 ID Mismatches

The most common class of bug. The system uses several IDs that must agree:

| ID | Generated by | Passed to | Pitfall |
|----|-------------|-----------|---------|
| `agent_id` | Config (`agent.yaml`) | Engine, TUI | "default" vs "breqy" — the TUI sends "default", engine must resolve to "breqy" |
| `session_id` | `SessionManager.create_session()` | Agent subprocess, messages | Agent must use the real session ID, not a hardcoded placeholder |
| `message_id` | `generate_prefixed_id("msg")` | Event bus, TUI | Must be unique per message |

**Check first:** If messages aren't flowing, verify that `agent_id` and `session_id` match across processes. Print/log them at each boundary.

### 2.2 Missing Event Handlers

Textual uses message passing. If a widget posts a `Message` and no ancestor has an `on_<message_name>()` handler, the message silently dies.

**Symptom:** User action does nothing. No error, no log, just silence.
**Check:** Verify the handler exists with the exact method name `on_<message_class_name>` using Textual's snake_case conversion.

### 2.3 Agent Subprocess Exits Immediately

The agent runtime's `main()` must call an async listen loop (`run()`) that blocks on `A2AClient.listen()`. If `main()` only calls `start()` and returns, the subprocess exits.

**Symptom:** Agent shows as connected briefly then disappears.
**Check:** Verify `main()` calls `run()` and that `run()` has an async loop awaiting `self.client.listen()`.

### 2.4 Foreign Key Constraint Errors

SQLite enforces FK constraints. If you spawn an agent with a `session_id` that doesn't exist in the sessions table, every DB write fails.

**Symptom:** `FOREIGN KEY constraint failed` in engine logs.
**Check:** Ensure `session_manager.create_session()` is called **before** `agent_spawner.spawn()`.

### 2.5 `_NullProvider` Yielding Nothing

`runtime.py` has a `_NullProvider` fallback whose `stream()` method uses `if False: yield` — it yields nothing. If the real `ModelProvider` isn't injected, the agent produces empty responses.

**Symptom:** Agent responds but content is empty string.
**Check:** Verify agent runtime receives a real provider, not `_NullProvider`. Check config loading and DI wiring.

### 2.6 Subprocess Pipe Buffer Full

If `subprocess.Popen` uses `stdout=PIPE, stderr=PIPE` but the parent never reads from the pipes, the OS pipe buffer (typically 64KB) fills and the subprocess blocks on the next write.

**Symptom:** Agent hangs after running for a while. No crash, no error.
**Check:** Verify `AgentSpawner` either reads from pipes, redirects to files, or uses `DEVNULL`.

## 3. Debugging Workflow

### Step 1: Identify Which Process Failed

```
# Is the engine running?
breqy engine status

# Check engine logs
cat .breqy/logs/engine.log | tail -50

# Check agent logs
cat .breqy/logs/agent-breqy.log | tail -50

# Check TUI logs
cat .breqy/logs/tui.log | tail -50
```

If log files don't exist, the observability system hasn't been implemented yet. See `docs/plans/2026-03-28-observability.md`.

### Step 2: Trace the Message Flow

A user message follows this path:

1. **TUI:** User presses Enter → `MessageInput` posts `MessageSubmitted` → `BreqyApp.on_message_submitted()` creates `MessageSentEvent(role=USER)` → sends via `A2AClient`
2. **Engine:** `A2AServer` receives `Envelope` → `_handle_user_message()` persists message → publishes `MessageSentEvent` to event bus → dispatches `AgentWorkRequestedEvent` to agent
3. **Agent:** `AgentRuntime.run()` receives `AgentWorkRequestedEvent` → calls `handle_work()` → streams from `ModelProvider` → sends `MessageSentEvent(role=AGENT)` back to engine
4. **Engine:** Receives agent response → persists → broadcasts `MessageSentEvent` to TUI
5. **TUI:** `BreqyApp._handle_engine_event()` receives event → routes to `ChatScreen.handle_message_sent()` → renders in `ChatView`

If the message stops at any step, the bug is in the transition to the next step.

### Step 3: Check ID Consistency

At each boundary crossing, verify:
- `session_id` is the same real session ID everywhere (not "runtime", not None)
- `agent_id` is "breqy" (not "default") after engine resolves it
- `message_id` is present and prefixed with "msg_"

### Step 4: Check Textual Widget Layout

If the TUI renders but input is invisible or widgets overlap:
- Every widget needs `DEFAULT_CSS` with explicit `height` constraints
- `height: auto` with no content = widget claims full parent fraction
- `height: 1fr` for scrollable content areas (ChatView, TaskPanel, ToolPanel)
- `height: auto; max-height: N` for fixed-size bars (AgentStatusBar, MessageInput, ControlBar)
- Check focus: `on_mount()` should call `self.query_one("#message-input").focus()`

## 4. Testing Patterns for Runtime Bugs

### Mocking A2A Communication

```python
from unittest.mock import AsyncMock, MagicMock

client = AsyncMock(spec=A2AClient)
client.listen = AsyncMock(return_value=async_generator_of_envelopes)
```

### Testing Textual Widgets

```python
async with app.run_test() as pilot:
    # Verify widget existence
    widget = app.query_one(MessageInput)
    assert widget is not None

    # Verify layout — widget must be on screen
    assert widget.region.y < app.size.height

    # Verify focus
    assert app.focused is widget
```

### Testing Event Flow

```python
# Verify handler exists
assert hasattr(app, "on_message_submitted")

# Verify event is sent to engine
app.send_event = AsyncMock()
await app.on_message_submitted(MessageSubmitted(content="hello"))
app.send_event.assert_called_once()
event = app.send_event.call_args[0][0]
assert event.role == MessageRole.USER
```

## 5. Known Gaps (As of 2026-03-28)

These are known issues that may affect debugging:

| Gap | Impact | Workaround |
|-----|--------|------------|
| No log files yet | Can't check process logs | Run in foreground, watch stderr |
| Agent runtime has no logging | Can't trace agent behavior | Add temporary print() statements |
| stdlib logging not configured in A2A | A2A layer log calls go nowhere | Migrate to structlog per observability spec |
| `complete_stream()` never called | Streaming buffer never flushed to display | May see partial/missing agent responses |
| No local echo of user messages | User doesn't see their own message in chat | Must wait for engine round-trip |

See `docs/plans/2026-03-28-observability.md` for the approved design to fix all logging gaps.
